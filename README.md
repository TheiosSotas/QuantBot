# QuantBot — modular paper trading

Τοπική προσομοίωση BTC/USDT perpetual futures με Qwen2.5 14B. Παίρνει δημόσιες τιμές από Binance και **δεν υποβάλλει πραγματικές εντολές**. Οι προμήθειες και οι χρηματοδοτικές χρεώσεις παραμένουν εκτός υπολογισμών σε αυτή την έκδοση.

## Εκκίνηση στα Windows / PowerShell

Απαιτούνται Python 3.10+ και Ollama με το υπάρχον `qwen2.5:14b` ήδη διαθέσιμο. Η εγκατάσταση Python dependencies δεν κατεβάζει ή αλλάζει μοντέλο AI.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe quant_bot.py
```

Το `python main.py` είναι ισοδύναμο. Το dashboard ανοίγει σε ελεύθερη θύρα του `127.0.0.1`. Για διαφορετικό φάκελο λογαριασμού ή εκκίνηση χωρίς browser:

```powershell
.\.venv\Scripts\python.exe quant_bot.py --data-dir E:\QuantBot-account --no-browser
```

Το πρόγραμμα δεν ζητά API keys ανταλλακτηρίου. Αν το Ollama λείπει ή αποτυγχάνει, οι ανοιχτές εικονικές θέσεις συνεχίζουν να ελέγχονται εφόσον υπάρχουν έγκυρες φρέσκες τιμές.

## Ιστορικό λογαριασμού και συνολικές προστασίες

Η συνολική αξία υπολογίζεται ως διαθέσιμο κεφάλαιο συν μη πραγματοποιημένο PnL της ανοιχτής θέσης. Κάθε έγκυρη τιμή αποθηκεύει την τρέχουσα κατάσταση σε μία συναλλαγή SQLite. Το ιστορικό κρατά δείγμα ανά 60 δευτερόλεπτα από προεπιλογή, καθώς και σε εισόδους, προσθήκες, εξόδους, μετακινήσεις stop και μεταβάσεις των συνολικών προστασιών. Περιλαμβάνει ώρα παρατήρησης/τιμής, cash, unrealized PnL, equity, peak, drawdown, notional και έκθεση. Σε μη θετικό equity ο λόγος έκθεσης αποθηκεύεται ως 0 επειδή δεν ορίζεται χρήσιμο ποσοστό· το notional παραμένει διαθέσιμο και νέες είσοδοι αποκλείονται.

Στο dashboard εμφανίζονται τα τελευταία 200 δείγματα, οι ενεργές παύσεις και οι τελευταίες 20 αποφάσεις με αποτέλεσμα και λόγο αποδοχής/απόρριψης. Το πλήρες ιστορικό παραμένει στη SQLite. Το `/api/history` δίνει τα ίδια περιορισμένα ιστορικά· το `/api/state` περιλαμβάνει τις ρυθμίσεις και την τρέχουσα κατάσταση προστασίας. Τα ιστορικά ανακτώνται από ανεξάρτητες read-only συνδέσεις, ώστε να μην περνά η σύνδεση εγγραφής στα HTTP threads.

**Οι νέοι περιορισμοί είναι αρχικά ανενεργοί, όπως επιλέχθηκε.** Ενεργοποιούνται ρητά με επιλογές εκκίνησης:

| Επιλογή | Τιμή και συμπεριφορά |
|---|---|
| `--daily-loss-limit` | Κλάσμα μεταξύ 0 και 1· απουσία σημαίνει ανενεργό |
| `--max-account-drawdown` | Κλάσμα μεταξύ 0 και 1· απουσία σημαίνει ανενεργό |
| `--cooldown-seconds` | Διάρκεια παύσης μετά από κάθε κλείσιμο· 0 σημαίνει ανενεργό |
| `--equity-sample-seconds` | Θετικό διάστημα ιστορικού· προεπιλογή 60 |

Για παράδειγμα, `--daily-loss-limit 0.03` δηλώνει 3%. Είναι παράδειγμα σύνταξης, όχι προτεινόμενο όριο. Τα υπάρχοντα όρια ανά θέση παραμένουν ενεργά ανεξάρτητα από τις νέες επιλογές.

Η ημερήσια βάση δημιουργείται στην πρώτη φρέσκια τιμή της ημέρας **UTC**. Περιλαμβάνει τις μεταβολές ανοιχτών θέσεων από εκείνη τη βάση. Μετά από διακοπή που περνά τα μεσάνυχτα, η νέα βάση είναι το πρώτο παρατηρημένο equity της νέας ημέρας, όχι μια επινοημένη τιμή στις 00:00. Το ημερήσιο latch παραμένει μέχρι την πρώτη φρέσκια τιμή επόμενης UTC ημέρας, ακόμη κι αν η τιμή ανακάμψει. Το συνολικό peak και το latch μέγιστου drawdown διατηρούνται και σε επόμενες ημέρες.

Παύση σημαίνει αποκλεισμό νέας εισόδου ή προσθήκης. Το stop/target και το επιτρεπτό κλείσιμο θέσης συνεχίζονται με έγκυρες τιμές. Το restart, η αλλαγή των CLI ορίων σε ανενεργά ή η ανάκαμψη της αγοράς δεν σβήνουν ένα ήδη ενεργοποιημένο latch. Δεν υπάρχει αυτόματη άρση του συνολικού drawdown latch ή κουμπί reset σε αυτή την έκδοση. Νέος ανεξάρτητος λογαριασμός δημιουργείται μόνο με διαφορετικό `--data-dir`· δεν διαγράφουμε ενεργή βάση για να παρακάμψουμε παύση. Αν το ρολόι γυρίσει πίσω, αποκλείεται νέο ρίσκο μέχρι να επανέλθει, χωρίς να αναβάλλεται μια ήδη απαιτούμενη έξοδος.

Οι παλιές βάσεις αναβαθμίζονται αυτόματα στο schema 1 χωρίς να χάνονται θέσεις/συναλλαγές. Οι βάσεις προστασίας αρχικοποιούνται στην πρώτη φρέσκια τιμή μετά την αναβάθμιση: δεν κατασκευάζεται αναδρομικό ιστορικό ή peak που δεν είχε αποθηκευτεί. Κρατήστε αντίγραφο του φακέλου λογαριασμού με σταματημένο bot πριν από αναβάθμιση. Βάση νεότερου, μη υποστηριζόμενου schema απορρίπτεται.

Κάθε ολοκληρωμένη απόφαση καταγράφεται με `ACCEPTED`, `REJECTED` ή `NO_ACTION`, ώρες αιτήματος/ελέγχου, κερί, model, snapshot και reason code. Καταγράφονται επίσης ληγμένες αποφάσεις, λανθασμένο schema, αποτυχία μοντέλου και έτοιμες αποφάσεις που απορρίπτονται επειδή λείπουν έγκυρα δεδομένα. Μη πεπερασμένες ή μη αναπαραστάσιμες τιμές αποθηκεύονται ως `null` στο περιορισμένο audit payload. Ενδεικτικοί λόγοι: `AI_DECISION_EXPIRED`, `DUPLICATE_CANDLE`, `POSITION_CHANGED`, `STRATEGY_FILTER`, `LOW_CONFIDENCE`, `RISK_BUDGET`, `MAX_TRANCHES`, `DAILY_LOSS_LIMIT`, `MAX_DRAWDOWN`, `COOLDOWN`. Σε πραγματική αποτυχία εγγραφής δεν είναι δυνατή η εγγυημένη καταγραφή του σφάλματος στην ίδια αποτυχημένη βάση· εμφανίζεται σφάλμα υγείας, χωρίς μερική εγγραφή fill/audit/history.

Οι προστασίες και η καταγραφή δεν αποτελούν backtesting, αξιολόγηση κερδοφορίας ή αλλαγή μοντέλου. Replay, Optuna και σύγκριση νέων AI παραμένουν επόμενο πακέτο.

## Συμπεριφορά και όρια

- Το Qwen παραμένει `qwen2.5:14b`. Δεν ενσωματώθηκαν Freqtrade, TradingAgents ή άλλα trading frameworks.
- Οι αποφάσεις γίνονται ανά νέο κλεισμένο ωριαίο κερί. Ο έλεγχος προστασίας στοχεύει σε κύκλο 5 δευτερολέπτων και δεν περιμένει το AI. Τα αιτήματα δεδομένων και η σύνδεση εξακολουθούν να επηρεάζουν την πραγματική καθυστέρηση.
- Οι SMA συμβάσεις RSI/ATR παραμένουν όπως πριν. Χρησιμοποιείται μεγαλύτερο ιστορικό προθέρμανσης EMA και έλεγχος πληρότητας δεδομένων.
- Τα defaults στο `Config` είναι 1% σχεδιασμένο ρίσκο ανά είσοδο, 3% συνολικό σχεδιασμένο ρίσκο θέσης και ανώτατο notional ίσο με 1x equity. Το τελευταίο είναι νέο ρητό όριο έκθεσης. Δεν επιβάλλεται κατώτατο μέγεθος συναλλαγής όταν δεν υπάρχει διαθέσιμο budget.
- Το stop μπορεί να βελτιωθεί αλλά δεν χαλαρώνει από μια προσθήκη. Μετά από προσθήκη ελέγχεται η νέα μέση είσοδος και μπορεί να πάψει να ισχύει η ένδειξη stop-at-entry.
- Οι μοντελοπαραγόμενες ιδέες μετά από ζημιά αποθηκεύονται για μελέτη και **δεν αλλάζουν αυτόματα τους κανόνες**.
- Η αναγραφόμενη απόδοση συναλλαγής είναι η κίνηση της τιμής, όχι απόδοση ολόκληρου λογαριασμού ή περιθωρίου.

## Αποθήκευση και μεταφορά παλαιών δεδομένων

Ο φάκελος λογαριασμού περιέχει `quantbot.sqlite3` και το παράγωγο `trades.csv`. Μαζί με τη βάση μπορεί να υπάρχουν SQLite `-wal`/`-shm` αρχεία. Μην αντιγράφετε μόνο τη βάση ενώ το πρόγραμμα γράφει· σταματήστε την εφαρμογή πριν από απλή αντιγραφή φακέλου.

Στην πρώτη εκκίνηση χωρίς υπάρχουσα βάση εισάγονται, αν υπάρχουν, τα `trades.csv` και `quant_memory.json` από τον ίδιο φάκελο. Η εισαγωγή γίνεται μία φορά. Η αρχική CSV παραμένει ανέπαφη κατά την εισαγωγή, και ενημερώνεται ως export όταν κλείσει νέα θέση. Για καινούριο λογαριασμό χρησιμοποιήστε διαφορετικό `--data-dir`.

Η νέα έκδοση αποθηκεύει τις ανοιχτές θέσεις και όλες τις προσθήκες. Δεν μπορεί να ανακτήσει παλιές ανοιχτές θέσεις που δεν είχαν ποτέ καταγραφεί από την προηγούμενη έκδοση. Αλλαγή συμβόλου ή timeframe στον ίδιο αποθηκευμένο λογαριασμό απορρίπτεται. Δεν επιτρέπονται δύο instances στον ίδιο φάκελο.

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check --config pyproject.toml .
.\.venv\Scripts\python.exe -m ruff format --config pyproject.toml --check .
```

Οι δοκιμές χρησιμοποιούν εικονικά δεδομένα και προσωρινούς φακέλους. Καλύπτουν καθυστέρηση/αποτυχία AI, exits πριν από additions, διατήρηση stop, φίλτρα, όρια έκθεσης, μη έγκυρα δεδομένα, rollback βάσης, αποτυχία CSV και επανεκκίνηση. Δεν αποδεικνύουν κερδοφορία και δεν αποτελούν live έλεγχο Binance/Ollama.

Το `requirements-lock.txt` καταγράφει τις ακριβείς εκδόσεις dependencies που χρησιμοποιήθηκαν στον τοπικό έλεγχο Windows/Python 3.10. Για διαφορετικό λειτουργικό προτιμήστε τα κοινά `requirements*.txt`.
